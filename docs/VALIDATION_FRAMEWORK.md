# Validation framework (Phase 7)

FORGE distinguishes three activities and never mixes them:

| Activity         | Question                                                                                              | Evidence in FORGE                                                                   |
| ---------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **Verification** | Is the model solved correctly?                                                                        | Convergence studies, analytical references (RC τ), replay consistency, solver tests |
| **Calibration**  | Which parameter values make the model fit these data?                                                 | `CalibrationRecord` (see MODEL_CALIBRATION.md)                                      |
| **Validation**   | Does the model agree with **independent** measured data, within stated criteria, over a stated range? | `ValidationRecord`                                                                  |

## Datasets

CSV (`name [unit]` headers) or JSON import, ≤ 5 MB. Timestamps must be strictly increasing; empty, `NA` and non-numeric cells are **missing** (not zero) and counted. Provenance is recorded: origin, instrument, collection date, operator, notes and an explicit **synthetic** flag. FORGE ships **no measured laboratory data**; any dataset generated by a program must be flagged synthetic.

## Validation records

`errorMetrics` compares a dataset column with a run's recorded signal on the dataset's timestamps (interpolated simulation values; observations outside the simulated span excluded): n, MAE, RMSE, max |error|, bias, and coverage of the observation uncertainty band when the column declares one.

Status:

- `agrees` / `disagrees` — independent, non-synthetic data with an acceptance criterion (metric ≤ threshold);
- `not-assessed` — no acceptance criterion given;
- `not-independent` — the dataset was used for calibration;
- `synthetic-only` — the dataset is flagged synthetic.

Each record states the operating range it covers.

## Experiment-level status

`validationStatus()` counts only `agrees` records. Without one, the experiment reads: _"Not empirically validated: no independent, measured (non-synthetic) dataset agrees with this model under stated criteria."_ With some: _"Agrees with N independent measured dataset(s) within the stated criteria, for: ⟨ranges⟩. Not validated outside these conditions."_

As shipped, every demonstration experiment is **not empirically validated**. The arm and ultrasonic models use generic, unvalidated actuator and sensor parameters (Phase 5/6); the RC study is verified against the analytical solution, which is verification, not validation.
